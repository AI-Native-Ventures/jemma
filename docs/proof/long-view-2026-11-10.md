# P52a Long view proof, 10 Nov 2026

## Result

The `long_view.requested` event ran for each of the 5 seeded learners in a fresh `start` sandbox on a local agent worker (port 8755, `AI_MODE=cache`). All 5 events settled as `done` on the first attempt. 4 of them asked the model once. Sipho has no pattern in his records, so code saved an empty list and the model was not asked. A sixth event, Amina again with a newer Class Test 1 in her marks, asked the model once more. The 5 answers are stored in `ai_replays`.

A second fresh `start` sandbox ran the same 6 events with the worker in `AI_MODE=replay`. All 6 settled as `done`, with zero replay misses and zero model calls, and every case saved the same patterns as in the first run. So the prompt reaches the model the same way in every sandbox: no ids and no date of the day change what the replay key is made from.

Real time for one update, from the event row being made to `finished_at`: 29 to 46 seconds with a model call, 6 to 9 seconds without one. The rules page asks for about 10 minutes per update, so that number can be shortened to "under a minute" for this model on this day. Free models are slow and uneven, so treat it as one measurement.

## The rule behind the sixth event

A pattern needs 3 or more terms in a row that all meet the threshold. It may end at the family's latest term with data, or at the term with data just before it. When it ended one term before the latest, the candidate carries `sinceThen`: the newest term (better than a struggle, or weaker than a strength) with its sources. The stored pattern keeps that newest result as a last entry in `terms` flagged `sinceThen: true`, and its sources are part of the evidence. A pattern that ended two or more terms with data ago is not a candidate. This way one different result does not hide a pattern that held, and the teacher sees the newer result next to it. The prompt (`jobs/long_view.md`) tells the model to say plainly that the newest result was better or weaker, name the test, and still describe the earlier run.

This changed the model's input, so the first recording (4 answers) was thrown away and everything below was recorded again with the final prompt. The 4 old rows are still in `ai_replays` under keys nothing asks for any more.

## Run setup

- Supabase project: `jemma-dev` only. Two synthetic `start` sandboxes (one per run), both deleted when the run ended.
- Worker: local `wrangler dev` on port 8755, local queue, run through `POST /events` with the shared secret, as the web app does.
- Model: `LLM_PROVIDER=openrouter`, `LLM_MODEL=nvidia/nemotron-3.5-super-vl:free`. `LLM_MODEL_FALLBACKS` was left empty for the run, so a failure could not fan out to a second model and the call count stayed bounded.
- Cap: at most 15 model calls were allowed for the packet. To count them exactly, a temporary counter was put around the raw provider model inside the retry layer (so retries count too) with a hard stop. It logged one line per real provider call. It was not committed and `packages/profiling/src/ai/models.ts` is unchanged in the branch.
- Driver: `packages/profiling/scripts/long-view-proof.ts`. It makes the sandbox, queues one event at a time, waits for it, then reads the saved patterns. For the sixth event it first adds Class Test 1 (written in Term 3 of the class year, 3 of 4 fractions answers right) to Amina's marks.

## What the data shows in the later demo stages

The long history is in every stage, but this year's marked answers join it. In the `marked` stage Amina's fractions terms are Term 1 30%, Term 2 40%, then Term 3 63% (the Term 3 history paper, 16 answers) and Term 4 67% (Class Test 1, 9 answers). Her struggle (Grade 5 Term 3 to Grade 6 Term 2) therefore ended two terms with data ago, which is not a candidate: she keeps her shapes strength and has no fractions pattern in that stage. The other four learners keep the patterns they have in `start`. The `marked` stage test (`packages/profiling/test/long-view.test.ts`) asserts this and only runs in Q4 of 2026, because the Term 3 paper is dated 25 Sept 2026 and Class Test 1 takes the day the sandbox is made. If the rule is widened to allow two newer terms, that test and this paragraph change with it. If a pattern was saved earlier, the next `long_view` run deletes it when it is still a draft and switches it off (`active = false`) when the teacher has already touched it.
